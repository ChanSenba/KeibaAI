# 競馬AI 仕様書

2026-10-12 時点。各スレッドの報告とコードをもとにまとめた。数字は報告にあるものだけを載せ、推測は「推測」と明記している。

## 1. 目的と全体像

JRA（中央競馬）の全レースについて、各馬の勝率を予測し、オッズと組み合わせて「買うか見送るか」と金額配分まで示す個人用ツール（リポジトリ ChanSenba/KeibaAI、Python、Windows）。2026-10-11 に決めた方針は次の4点。

- 対象は中央競馬。まず予想の表示、次にオッズからの買い目提案
- 動かす環境は Windows PC。追加費用なし（JRA-VAN は使わず、契約済みの netkeiba を使う）
- データは個人利用に限り、公開しない（`data/` は Git 管理外）
- 検証は必ず時系列で分け、回収率まで確かめる

**処理の流れ**

1. 取得：netkeiba から結果・出馬表・オッズ・血統・調教評価を取り、ページを `data/cache/` に保存して SQLite（`data/keiba.db`）に入れる
2. 特徴量：そのレースより前の結果だけから、馬・騎手・厩舎・血統・ラップ・調教評価などの数値を作る
3. モデル：LightGBM で各馬の勝率（と3着以内率）を出す。必要に応じて市場オッズの確率と混ぜる
4. 表示：期待値と印（◎○▲△☆★）を予想画面に出す
5. 買い方：1レースごとに全券種の期待値を計算し、ケリー基準で金額を配る
6. 検証：過去レースで買い方ルールを再現し、回収率と信頼区間を見る
7. 毎週：予想を保存し、結果と照合して回顧を書く

**役割分担**：コードの変更と PR はクラウド側の Claude が行い、netkeiba への通信と実行は尚さんの PC 側のセッションが行う（クラウド環境から netkeiba へは接続できないため）。

**現在地（2026-10-12 時点）**：データ収集から買い方提案までの仕組みは main に入っている。一方、検証では「オッズに足せる情報をほぼ持っていない」という結果で、回収率が100%を超える買い方はまだ見つかっていない（第8章）。血統と調教評価を入れた再検証が次の山場。

**調教について分かったこと**（PC で実ページを確認）

- レースの調教ページ（`oikiri.html?race_id=…`）はログインなしで全頭の短評とA〜D評価が見え、過去のレース（2024年の未勝利戦）でも同じ

**調査で出た追加案（未実装）**：前走の相手関係（前走で戦った相手のその後の成績）、前走の敗因（大外枠・頭数）、初ダート・初芝の印。2016年のレース予想コメントを分析した論文を参照して挙がった案で、尚さんの「はい」待ち。

## 4. モデルと確率の出し方

**モデル**：LightGBM の二値分類（「1着か」「3着以内か」）。主な設定は learning_rate 0.05、num_leaves 31、min_data_in_leaf 50、feature_fraction と bagging_fraction は 0.8。分割は必ず時系列で、`--test-from` 以前を学習、以後を評価に使う。

**よく使う勝率の種類**

| 種類 | 使うもの | 位置づけ |
| --- | --- | --- |
| 勝率（能力） | 過去成績・騎手・調教師・レース条件など。オッズは使わない | 人気と違う見方を見るための基礎の確率 |
| 勝率（オッズ込） | 上に単勝オッズ・人気を加えたもの | オッズが取れないときは空 |
| 要素別の勝率 | 馬の質・適性・ローテーション・騎手厩舎・展開馬場・血統・調教などを別々のモデルで出す | どの要素が効いているかを見るため。`factors` で、総合と「総合+全要素」を含めて比べる |
| 混合勝率（ベンター方式） | モデルの勝率と、オッズから出した市場の確率を、レースごとの対数オッズで混ぜる | 「買い方」で使う確率 |

**混合の割合の決め方**：評価開始日の直前12か月の結果だけで決め、評価期間の結果は使わない。実データではモデル側の重みがほぼ0（-0.06）、オッズ側が1.06になった。つまり混合確率はほぼオッズどおりで、モデル独自の上積みは無い。

**期待値**：単勝の期待値 = 勝率 × 単勝オッズ。1を超えると、予測が正しいなら長い目で得になる目安。予想画面では「能力の期待値」と「オッズ込みの期待値」を出す。大穴は勝率の小さな誤差で期待値が大きく跳ねるため、買い方では「的中確率の下限」を設けている（第5章）。

**印の基準**（予想ページ・ファクター総合タブ）

| 印 | 基準 | 注意 |
| --- | --- | --- |
| ◎ ○ ▲ △ | 勝率の高い順（オッズがあればオッズ込み、なければ能力のみ） | ◎の単勝回収率は第8章を参照 |
| ☆ | 印のない馬のうち、能力の期待値がいちばん高く1を超える馬（穴馬候補） | 「得な馬」とは言えない |
| ★ | 能力の期待値 1.1 以上、かつ勝率 3% 以上、かつ単勝 30 倍以内 | 「モデルがオッズより高く評価している馬」の印。過去の検証では単勝回収率 76〜84% で、買えば得になる印ではない（画面にも記載） |

★の基準は、尚さんの「検証してから」という指示で、基準候補48通りを一度に比べて（`backtest --grid`）、「一番まし」だった組み合わせに決めた。この結果は収益の根拠ではなく、表示上の目印。

## 5. 買い方

指定した1レースについて、予想確率と当日オッズから、券種と金額配分を出す（`keibaai bets`、GUI の「買い方」）。尚さんが求めたのは、過去レースの券種比較ではなくこの「1レースごとの最適な買い方」。

**計算の順番**

1. モデルの勝率とオッズの確率を混ぜた勝率を作る（混ぜ方は直前12か月の結果で決める）
2. 勝率から1〜3着の並びの確率を出す（ハーヴィルの式を、人気馬の2〜3着を少し抑えるヘネリー版にしたもの）
3. 買い目ごとに期待値 = 的中確率 × 当日オッズを出し、期待値が1を超えて的中確率が3%以上のものだけを候補にする
4. 候補の中から、資金が長い目で最も増える配分（ケリー基準。既定は半分に抑える）を求め、100円単位にする

**対象券種**：単勝・複勝・馬連・ワイド・馬単・三連複・三連単（枠連はオッズを取得するが、買い目の計算対象に含めているかは確認していない）。複勝とワイドは幅のあるオッズの下限で計算する。

**資金配分の設定**

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| 使える資金（`--bankroll`） | 100,000円 | GUI では100円から指定できる |
| 1レースの上限（`--cap`） | 10,000円 | 超えると比率を保って縮める |
| ケリーの抑え方（`--kelly`） | 0.5（半分） | 期待値の高い買い目ほど多く張る |
| 的中確率の下限 | 3% | 大穴の期待値は誤差で跳ねるため候補から外す |
| 資金配分をしないモード | — | 「1点の金額」を指定し、期待値の高い順に同額ずつレース上限まで買う |

**少額資金の扱い**（PR #25、#26）

- 経緯：資金1,000円でスワンSが「見送り：100円に満たない配分」になった（ケリー配分がどれも100円未満に切り捨てられた）
- 対応：ケリー配分がどれも100円に満たないときだけ、期待値の高い買い目から100円ずつ買う
- 歯止め：初回の対応では1,000円のスワンSが8点・800円（資金の8割）になったため、使うのは資金の3割まで（最低1点）、期待値が1.05未満の買い目は入れないとした。この制限を入れた後の実データでの再確認結果は報告されていない（スレッドには最大でも300円ほどとの見込みという記述のみ）
- この代替配分はケリー配分より多めに張ることになるため、画面に注記を出す

**「見送り」**：期待値が1を超える買い目がないレースは「見送り」と表示する。控除率があるため、買わないのが答えのレースも出る。

**「その日の全レース」一括モード**：残りの資金を残りレース数で割った額を1レースの上限にして、合計が資金を超えないようにする。日付を選べ、予想が未実施ならその場で予想してから計算する。この一括モードは合成データで画面確認しただけで、実データでは未確認。

**実データでの動作確認**（2026-10-12 京都11R スワンS、確定オッズ）

- 初回：ワイドの大穴2点（計300円）、期待回収率 257%。的中確率が約1%で誤差が大きく、信用できないと判断（モデルの重みが-0.10で、確率がほぼオッズ由来だった）
- 的中確率 3% 以上に絞った後：ワイド 4-18 に500円、馬連 9-18 に200円、ワイド 1-12 に200円、ワイド 9-18 に200円、合計1,100円。どれか的中が21%、期待回収率126%
- ただしこの126%は、混合のオッズ側の重みが1.08と「オッズを少し強める」補正になっていることが主因で、モデル独自の根拠ではない。このレースの的中結果は確認していない
- このときは「モデルがオッズを超えている」とは言えない。血統や調教が揃ってモデルの重みがプラスになって初めて独自の期待値になる

**未検証・制約**：2〜3着の確率の式の定数は文献の値で、JRA の払戻で確かめていない。過去レースの券種ごとのオッズを集めていないため、馬連以降は過去の回収率を検証できない。期待回収率は「予想が当たっている前提」の数字。

## 6. GUIの各タブ

`KeibaAI.bat` をダブルクリック、または `keibaai-gui` でブラウザに操作画面が開く（Streamlit、http://localhost:8501、この PC からだけ）。上のメニューで切り替え、スマホ幅では左上のボタンになる。PC の設定に合わせてダークモードにもなる。終了するときは黒い画面（コンソール）を閉じる。

| タブ | できること |
| --- | --- |
| データ | 取得済みのレース数・期間、月別と競馬場別の件数、最近のレース |
| 取得 | 「先週末」「1か月」などのボタンか日付で期間を選んで取得。進み具合とログを表示。このボタンを押すと netkeiba へアクセスする |
| 再解析 | 保存済みページから DB を作り直す（通信なし） |
| 予想 | 出馬表の取得と予想。期待値の高い馬、レース別の表（印◎○▲△☆★、勝率、期待値、要素別の勝率の列）。1レースだけ取得・予想することもできる。列の見出しに ? の説明が付く。レース名が欠けたレースでエラーを起こす不具合を PR #33 で修正中（未マージ） |
| 買い方 | 日付とレースを選んで買い目と金額を出す。「その日の全レース」一括、資金配分のあり・なし（ケリー配分／同額）、資金100円から |
| ファクター | 出馬表を取得した日のレースを選ぶと、馬ごとの値がタブで見られる（学習しないのですぐ開く）。先頭の「総合」に各区分の重要な16列と、馬名の右に印・★・勝率・期待値。続く9区分のタブがある。各列の見出しに説明と「高いほうが良い／低いほうが良い／0に近いほうが良い」、各列の上位5頭を緑に着色（良し悪しが決まらない列は着色なし）。区分ごとのデータ状況（取得済み・一部・未取得）をカードで表示 |

| 回顧 | 保存した予想と結果の照合（◎が1着だった数、◎の回収率など） |

| 設定 | DB と保存済みページの場所 |

**ファクターの9区分**：脚質・馬齢・体重、適性、近走・ローテーション、騎手・厩舎、馬場・枠・展開、オッズのゆがみ、血統、調教、ラップ・ペース。

**画面の確認状況**：買い方の「全レース一括」と資金配分の切り替え、総合タブの勝率・期待値、★列は、合成データで見たか起動確認だけで、実データの画面では確認していない。ファクタータブの血統・ラップはテスト環境にデータがなく、画面で見ていない。

**ファクタータブの表示速度**（実測、PC：Ryzen 7 9800X3D、DB 31.9MB、血統取得と同時実行中）：`factor_values` 全体で約12.5秒（結果の読み込み1.2秒、特徴量の作成 5.8秒、後処理 5.5秒）。最初の報告の「約7秒」をこちらで置き換える。日付の索引は既にあり、DB の検索ではなく計算が重い。同じ日の二回目はキャッシュで速く、血統が500頭増えるごとに計算し直す（PR #32）。後処理を出馬表の隠れる騎に絞る改善は検討中。ファクタータブは netkeiba へアクセスしない。

## 7. CLIコマンド

Windows では `python -m venv .venv`、`.venv\Scripts\activate`、`pip install -e ".[dev]"` のあと、`keibaai <コマンド>` を実行する。`pytest` でテスト（報告時点で148件通過）。★印のコマンドは netkeiba へアクセスする。

| コマンド | 主なオプション | 内容 |
| --- | --- | --- |
| ★ `collect` | `--from` `--to`（YYYY-MM-DD） | 期間内のレース結果を取得して DB に保存。結果未掲載の日は飛ばす |
| `reparse` | — | 保存済みページから DB（ラップを含む）を作り直す（通信なし） |
| `train` | `--test-from` | 特徴量を作って学習し、1番人気基準・能力のみ・オッズありの3行を表示 |
| ★ `entries` | `--date` | 出馬表と単勝オッズを取得して保存。馬が0頭のレースは「保存済み」にしない |
| `predict` | `--date` | 各馬の勝率と期待値（印・★・要素別の勝率を含む）を表示 |
| ★ `pedigree` | `--limit`（0なら全部） | 馬ごとの血統を取得。出馬表の馬が先。止めても続きから |
| ★ `training` | `--limit` `--date` `--reparse` | 調教の評価を取得。`--date` は出馬表を取った日だけ取り直し、`--reparse` は保存済みページから読み直す |
| ★ `bets` | `--date` `--race-id` `--bankroll` `--cap` `--kelly` | 1レースの買い方（券種と金額配分）。先に `entries` |
| `factors` | `--test-from` | 要素別モデルの当たりやすさを総合と比べる |
| `backtest` | `--test-from` `--market` `--blend` `--ev` `--max-odds` `--min-p` `--grid` `--stake` | 過去レースに単勝の買い方ルールを当てはめて回収率を出す。`--grid` は期待値×勝率下限×オッズ上限を一度に試す |
| ★ `weekly` | `--today` | 前週の予想を結果と照合して回顧を書き、今週末の予想を保存 |
| `keibaai-gui` | — | GUI を起動（`KeibaAI.bat` でも可） |

**毎週の自動実行（`weekly`）**

- 予想を保存した日のうち今日より前の結果を取得し、予想と照合して `data/reviews/<日付>.md` に回顧を書く。回顧は事実（◎の着順、勝ち馬の予想順位とオッズ、期待値で買った場合の収支）だけで、外れた理由の推測は付けない
- 今週末（土・日）の出馬表とオッズを取得して予想を保存する（出馬表が未確定なら飛ばす）
- 予想は発走前の内容のまま残し、開催日の9時以降と開催日が過ぎたあとは書き換えない。何度実行しても、済んだ分は飛ばす
- Windows のタスクスケジューラに、木曜と月曜の夜21時に `KeibaAI-weekly.bat` を登録する手順が README にある。実際に登録されたかは確認していない。PC が起動していないと動かない（動かなかった週はあとから実行すれば取り戻せる）。実行記録は `data\weekly.log`
- `weekly` の実行部分が最初に main に入ったときに抜けていて、PR #13 で補った経緯がある。実ページでの `weekly` の動作確認は、出馬表の確認とあわせて 10/15 以降に行うと思われる（推測）

**よくあるトラブル**：`collect` の実行中は `keibaai.exe` がロックされ、`pip install -e` が WinError 5 で失敗する。そのときは取得の終了を待つか、`.venv\Scripts\python.exe -c "from keibaai.cli import main; main()" <コマンド>` で実行する。

## 8. 検証結果

結論：2026年の2,622レースで、モデルは1番人気やオッズだけの確率に勝てず、回収率が100%を超える買い方も見つかっていない。以下は各スレッドの報告にある数字だけを載せている（単勝を100円ずつ買った場合の回収率）。

**8-1. 最初の学習（1年分のデータ、2026-07-01 以降の924レースで評価）**

| モデル | 勝 AUC | 1番手的中 | 単勝回収率 |
| --- | --- | --- | --- |
| 基準：1番人気 | — | 35.8% | 83.8% |
| オッズなし（能力のみ） | 0.751 | 22.9% | 79.9% |
| オッズあり | 0.825 | 33.4% | 82.8% |

回収率の差（83.8% と 82.8%）は924レースでは誤差の範囲と報告された。データが1年分で馬ごとの過去成績が貯まっていないせいという見方は推測で、確認していない。

**8-2. 3年分のデータ、2026-01-01 以降の2,622レースで評価**

| モデル | LogLoss（小さいほど良い） | AUC | 単勝回収率 |
| --- | --- | --- | --- |
| オッズから出した勝率（1番人気基準） | 0.2049 | 0.837 | 79.6% |
| 能力のみ | 0.2240 | 0.785 | 77.8% |
| 能力＋オッズ | 0.2070 | 0.832 | 78.4% |
| 混合（ベンター方式） | 0.2048 | — | — |

混合の重みはモデル -0.06、オッズ 1.06。混合してもオッズ単独（0.2049）と同じで、上積みは無い。

**8-3. 要素別の効き（AUC、同じ 2,622 レース）**

| 要素 | AUC |
| --- | --- |
| 馬の質 | 0.775 |
| 適性 | 0.748 |
| 騎手・厩舎 | 0.726 |
| 展開・馬場 | 0.621 |
| ローテ | 0.615 |
| 総合 | 0.785 |
| 総合＋記事の全要素 | 0.789 |

血統は520頭分しか入っていない状態、調教は未取得の状態での結果。

**8-4. 買い方ルールの回収率（単勝、穴を含む、2026-01-01 以降）**

| ルール | 回収率 | 備考 |
| --- | --- | --- |
| 1番人気 | 79.4% | |
| ◎（勝率順位1位） | 77.8% | |
| 期待値≥1（能力モデル） | 70.8% | 全頭の半分以上を買うことになり、モデルが市場より大きく見積もる偏りが原因と報告 |
| 全頭買い | 74.3% | 控除率の目安 |

回収率の95%区間は60〜82%と報告（どのルールの区間かは報告に明記がない）。すべて100%を大きく下回る。

**8-5. 混合確率による期待値ルール（2026-01-01 以降）**

| ルール | 買い目 | 回収率 | 95%区間 |
| --- | --- | --- | --- |
| 期待値≥1.0 | 82点 | 112.1% | 33〜231% |
| 期待値≥1.2 | 18点 | 97% | — |
| 期待値≥1.5 | 7点 | 83% | — |

112.1%は82点だけの結果で、区間が100%をまたいでいるため「プラス」とは言えない。報告された解釈は、「今の特徴量（過去成績・騎手・調教師・馬場など）はオッズにすでに織り込まれていて、混ぜても上積みがない」。

**8-6. ★の基準の検証**

| 条件 | 対象 | 結果 |
| --- | --- | --- |
| ★基準案（期待値≥1.1・勝率≥3%・50倍以内、能力モデル） | 2025年以降6,077レース | 17,297点、回収率 78%（72〜84%）。平均でレース2.8頭に付く |
| 同じ基準を混合確率の期待値で | 2026年 2,622レース | 7レースのみ、回収率 82%（16〜162%） |
| 同じ基準を混合確率で | 2025年以降 | 56点・的中10回、回収率 115%（43〜202%）。区間が広く根拠にならない |
| 基準を 48 通りに変えたグリッド | 能力モデル | 回収率 68〜84%。100%を超える組み合わせはなし |
| 採用した★基準（期待値≥1.1・勝率≥3%・30倍以内） | グリッドで「一番まし」 | 回収率 76〜84%（画面でもこの範囲を注記） |

**8-7. 読み取り方と限界**

- 単勝の控除率は約20%なので、回収率が100%を超えるのはもともと難しい。人気や全頭買いがハズレでも 74〜80% になるのはそのため
- 検証に使ったオッズは確定オッズで、買う時点のオッズより低いことが多い。実際の成績は表より悪くなりがち
- 検証は単勝だけ。馬連以降は過去の券種オッズを集めていないため検証できない
- 血統が520頭分で調教が未取得の状態の結果。全頭の血統と調教評価を入れた再検証はこれから
- 基準をいくつも試して良い結果だけを選ぶと、たまたまの当たりを拾う。基準は先に決めて一度だけ評価する。★の基準をグリッドから選んだことはこの注意に触れ、★が「得な印」ではない理由の一つになる（推測）

## 9. 既知の制約と今後のフェーズ

**既知の制約**

- **優位性が未確認**：現状のモデルはオッズに足せる情報をほぼ持っておらず、★・☆や期待値の印は「買えば得になる」を示さない（第8章）
- **データ量**：結果は約3年分。血統は全頭取得の途中で、調教評価は未取得、調教タイムは会員ログインが必要で未取得
- **実ページ確認の残り**：出馬表・オッズの読み取りはスワンSでは動いたが、10/17 開催分は出馬表が未確定で確認できていない（10/15 夕方以降に確認）。毎週の自動実行も実ページでは未確認
- **検証の範囲**：単勝のみ。オッズは確定オッズで、実際に買うときより有利に出る。馬連以降の確率の式は文献の定数で、JRA の払戻で確かめていない
- **推定で作っている特徴量**：脚質とペース予想は推定の目安。ペース指数は RPCI ではなく、結果ページのラップ（前半3F−後半3F）での代用
- **実行環境**：netkeiba への取得は尚さんの PC でしか動かせない。PC がスリープすると取得が止まる（続きから再開可）。取得系のコマンドは同時に動かさない
- **メンテナンス**：ファクタータブの初回表示が約12.5秒、買い方は1レース約40秒（どちらも毎回学習・特徴量を作り直すため）。特徴量と学習済みモデルを保存して使い回す案は、今は見送り

**フェーズの状況**（尚さんが決めた順番）

| フェーズ | 状況 | 次にやること |
| --- | --- | --- |
| ① 精度を上げる | 3年分で学習し直し済み。オッズには勝てていない | 血統の全頭取得（10/13 23時ごろ）と調教評価の取得（約11時間）のあと、`factors` と `backtest --blend` を実データでやり直す |
| ② 今週のレースを予想 | `entries`・`predict`・GUI を main に実装済み | 10/15 夕方以降に 10/17 の出馬表を実ページで確認する |
| ③ 買い方を検証 | 単勝のルールを検証済み（100%超えなし）。1レースの全券種の買い方を実装済み | 血統・調教を入れて再検証。券種別の過去の回収率を見るには、結果ページの払戻表の取り込みが要る（提案済み、尚さんの返事待ちのまま） |
| ④ 自動で回す | `weekly` を実装済み（木・月 21時の登録手順あり） | タスクスケジューラへの登録と、実ページでの動作確認 |
